# OpenAI-compatible provider additions

Read this reference when adding or changing an entire OpenAI-compatible provider
behind Pi5 CLIProxyAPI. It captures provider-specific failures observed while
adding OpenCode Zen without turning current model counts into fixed rules.

## Configure and probe the upstream

Use CLIProxyAPI's `openai-compatibility` provider form with an explicit unique
prefix so its upstream IDs cannot collide with official or other provider
models. Preserve `force-model-prefix` when the deployment relies on namespaced
IDs. For OpenCode Zen, the working CLIProxyAPI shape uses `api-key-entries`
with one protected `api-key`, plus an explicit `models` list. Keep the provider
credential only in its protected live configuration; never copy the value into
a generated catalog, test fixture, log, or command output.

OpenCode Zen free models are IP-rate-limited. If the model defines
`rateLimit.checkHeader` and the request omits that header, Zen uses
`fallbackValue` instead of the real quota; that fallback can 429 immediately.
The official OpenCode client sends `x-opencode-client`, `x-opencode-session`,
`x-opencode-project`, `x-opencode-request`, and `User-Agent: opencode/<version>`.
Keep those headers on the CLIProxyAPI provider. A browser User-Agent that was
once used to avoid Cloudflare 1010 causes the fallback quota. If 1010 returns
again, diagnose it separately, but do not replace the CLI identification
headers to fix it. Do not rotate client IPs to evade the remaining quota.

Confirm both the configured upstream list and the authenticated live
`/v1/models` response. Do not shrink the configured catalog merely because
CLIProxyAPI temporarily cools a credential after 401, payment, or 429 responses
and omits models from the live list.

## Interpret OpenCode responses

- A free model can return HTTP 429 / `FreeUsageLimitError` when the CLI
  identification headers are missing, or when the real IP quota is exhausted.
- After the CLI headers are present, a 200 with model text is successful
  inference. `CPA/opencode/big-pickle` returned `PING` through Pi5 and Mac
  Cockpit on 2026-09-03.
- A paid model can reject the request when the workspace has no payment method
  or credits.
- Occasional `500 Internal server error` is OpenCode upstream, not a missing
  Cockpit route.
- A 404 `model_route_not_available` is different: it is generated by Cockpit's
  stale or missing live route and means the request did not reach OpenCode.

Do not probe every imported model when doing so may consume credits or trigger
cooling. Test representative free models unless the user explicitly authorizes
paid calls, document which models were actually tested, and do not claim that
the full imported catalog can answer successfully.

## Synchronize without creating false visibility

The desired namespaced chain is:

```text
upstream model -> opencode/<model> -> CPA/opencode/<model>
```

Synchronize the CLIProxyAPI configured set, Mac and CTPS provider catalogs,
their route snapshots and manifests, and each host's Codex catalog. Preserve the
host-specific official portion and context policy.

Selector presence and `/v1/models` presence are not route proof. During the
OpenCode installation, manifest `modelIds` made models visible while the route's
`upstreamModels` and the running matcher still held the old set. Require a real
Responses request after the Cockpit sidecar has been reloaded.

## Reload safely

Cockpit can retain a route snapshot in memory and rewrite disk files when it
regenerates the sidecar. Do not fight this with `chflags uchg`, read-only flags,
or a watcher that writes after process exit; those mechanisms broke normal
Cockpit persistence and complicated recovery.

For Mac, do not stop the sidecar from the task using it. Arrange a
user-controlled relaunch or an independent task that stays connected, then
verify the new process and live request.

For CTPS, first confirm both CTPS and dependent WSL tasks are idle. Keep
`codex_auto_restore_takeover_on_launch = false`, relaunch Cockpit in Windows
interactive Session 1, and confirm both `cockpit-tools` and
`cockpit-cliproxy` run there. If a timestamped Scheduled Task is used, delete it
and its exact temporary script after verification.

Never serialize the credential-bearing store through PowerShell
`ConvertTo-Json`; it can change a model catalog array into an object shaped like
`{Count, value}`. Validate that the provider catalog is still an array of string
model IDs before relaunch, not merely an array or object with the expected
count. Avoid cross-language replacement strings such as `${1}false` inside a
JavaScript template literal: the outer language may expand them and write
invalid JSON. Always parse the candidate after writing and before restarting.
